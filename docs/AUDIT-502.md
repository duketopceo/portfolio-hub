# 502 Bad Gateway — audit (Cloudflare → Traefik → portfolio-hub)

**Symptom:** Cloudflare shows “Bad Gateway (502)”. That means Cloudflare reached **something** upstream but the response was invalid or the origin failed before a proper HTTP response.

**Request path (typical):**  
Browser → **Cloudflare edge** → **your origin** (public IP / tunnel) → **Traefik** → **portfolio-hub container :3000**

502 is **not** generated by this Next.js app’s route handlers in normal operation; it usually means **Traefik** (or another proxy) could not get a valid response from the backend.

---

## 1. What must be true (repo + runtime)

| Layer | Requirement | In repo |
| --- | --- | --- |
| **App listens** | Bind `0.0.0.0:3000` | `Dockerfile`: `HOSTNAME=0.0.0.0`, `PORT=3000` |
| **Swarm networking** | Same overlay as Traefik | `docker-compose.yml`: `networks: [traefik-public]` |
| **Traefik → container** | Use overlay network, not wrong NIC | Label `traefik.docker.network=traefik-public` |
| **Router match** | `Host` matches browser | `Host(\`luke-the-duke.com\`) \|\| Host(\`www.luke-the-duke.com\`)` |
| **TLS on Traefik** | Entrypoint + cert resolver exist on **your** Traefik | Labels `websecure`, `tls.certresolver=cloudflare` — **must match Traefik static config** |
| **Backend port** | Traefik forwards to app port | `loadbalancer.server.port=3000` |
| **Healthy backends** | If Traefik LB healthcheck fails for **all** replicas → 502/503 | See §3 |

---

## 2. Failure buckets (most → least common)

### A. Traefik cannot reach the container (wrong network / DNS on overlay)

**Cause:** Traefik resolves the service IP on a network where the task is not reachable.

**Mitigation:** `traefik.docker.network=traefik-public` (in `docker-compose.yml`).

**Verify (on a Swarm manager):** Swarm overlay networks are usually **not** `attachable`, so `docker run --network traefik-public` fails with *network not manually attachable*. Use one of these instead:

**DNS note:** `docker service ls` shows **`portfolio_portfolio`** (stack + service). Swarm’s embedded DNS name for the service is the **compose service key** — here **`portfolio`** (see `services:` in `docker-compose.yml`). Use **`http://portfolio:3000`** from another container on the same overlay, not `http://portfolio_portfolio:3000` (that hostname often does not resolve → `Could not resolve host`).

```bash
# 1) App responds inside a portfolio task (localhost — no overlay attach needed)
CID=$(docker ps -q -f name=portfolio_portfolio | head -1)
[ -n "$CID" ] && docker exec "$CID" wget -qO- --timeout=3 http://127.0.0.1:3000/api/health
```

```bash
# 2) Same DNS path Traefik uses: reuse Traefik’s network namespace, then curl by Swarm DNS name
TID=$(docker ps -q -f name=traefik | head -1)
[ -n "$TID" ] && docker run --rm --network "container:$TID" curlimages/curl:latest -sS \
  http://portfolio:3000/api/health
```

Expect HTTP **200** body or JSON. If **(2)** fails but **(1)** works, Traefik’s routing/network is still wrong.

---

### B. Traefik static config ≠ labels (entrypoint / cert resolver names)

**Cause:** Labels reference `entrypoints=websecure` and `tls.certresolver=cloudflare`. If your Traefik file uses `web` / `websecure` with different names, or resolver `letsencrypt` instead of `cloudflare`, the router never attaches or TLS fails.

**Action:** Compare `docker-compose.yml` labels to Traefik’s `entryPoints` and `certificatesResolvers` names. They must match **exactly**.

---

### C. Traefik load balancer healthcheck marks all servers down

**Cause:** Traefik LB healthcheck path fails for every replica (timeout, 500, connection reset) → no healthy backend → **502**.

**Risk:** `/api/repos` runs `getEnrichedProjects()` (GitHub fetch). Slow or failing upstream GitHub calls can delay or error responses during checks.

**Mitigation:** Use a **dedicated** lightweight route: **`GET /api/health`** (200, no GitHub). Prefer pointing Traefik LB healthcheck (and optionally Docker `HEALTHCHECK`) at `/api/health`.

---

### D. Cloudflare ↔ origin TLS mismatch

**Cause:** Cloudflare **SSL/TLS** mode **Full (strict)** requires a valid cert on the origin. If Traefik isn’t issuing certs yet or hostname mismatch, handshake fails → 502 at Cloudflare.

**Actions:** Try **Full** (not strict) temporarily, or fix Let’s Encrypt/Cloudflare DNS challenge on Traefik. Grey-cloud DNS to bypass Cloudflare for testing.

---

### E. DNS / traffic not going to Traefik

**Cause:** `A`/`AAAA`/`CNAME` for `luke-the-duke.com` points to the wrong IP, or **Cloudflare Tunnel** (`cloudflared`) is used with a **different** public hostname than Traefik expects.

**Action:** Confirm which path serves production (direct to Swarm IP vs tunnel). Tunnel config must route `luke-the-duke.com` to the correct internal service (Traefik or app).

---

### F. Host header / redirect loops

**Cause:** Another router catches the same Host with higher priority, or HTTP→HTTPS redirect misconfigured.

**Action:** Inspect Traefik dashboard / logs for duplicate routers on the same Host.

---

## 3. Application health endpoint (recommended)

| Route | Purpose |
| --- | --- |
| `GET /api/health` | Liveness: **200** JSON, **no external calls** — safe for Traefik + Docker healthchecks |
| `GET /api/repos` | Data + can hit GitHub — **not** ideal as sole health probe |

After deploy, confirm:

```bash
curl -fsS https://luke-the-duke.com/api/health
```

## 4. Commands (copy-paste)

```bash
# Service state
docker service ps portfolio_portfolio --no-trunc

# App logs
docker service logs portfolio_portfolio --tail 100

# Liveness inside a task (works when traefik-public is not attachable)
docker exec "$(docker ps -q -f name=portfolio_portfolio | head -1)" wget -qO- http://127.0.0.1:3000/api/health

# Traefik’s view of the service (optional — curl image + Traefik container name matching *traefik*)
# Hostname is the compose service name "portfolio", not "portfolio_portfolio"
TID=$(docker ps -q -f name=traefik | head -1)
docker run --rm --network "container:$TID" curlimages/curl:latest -sS -i http://portfolio:3000/api/health | head -20
```

---

## 5. Optional: attachable overlay (advanced)

If you really want `docker run --network traefik-public`, the network must be created with **`--attachable`** (often done when the network is first created). Recreating a production network affects every service using it — not recommended without a maintenance window. Prefer **`docker exec`** / **`--network container:$TID`** (Traefik container) above.
