## 4. Live URLs are the scarcest asset

Only **28 of 138** repos have a homepage URL. Among the missing flagships, exactly
one (`server-001`) does. That means most additions will render as repo cards, not
demos — and a reviewer's next click lands on GitHub rather than something running.

If a demo matters more than breadth, the highest-leverage work is **deploying three
or four of the flagship missing repos** rather than adding all 33.

---

## 5. Recommended audition order

1. **Fix the six failing catalog entries first** — they are live now and are the
   empty-click risk. Cheapest: write the missing READMEs.
2. **Add the four highest-signal missing repos**: open-military-hardware-db (4★),
   server-001 (live URL), wisp, open-computer.
3. **Add the plugin family as one grouped entry** rather than six separate cards —
   `a0-plugin-*` reads as a suite, not six projects.
4. **Group the Omarchy plugins** the same way.
5. Leave scaffolds and shells out until they have history.

## Reproducing

```bash
python3 scripts/audit-repo-audition.py        # writes docs/CATALOG-AUDIT.md
```

Requires `gh` authenticated. Excludes forks and archived repos by default.
Python rather than Node because it needs no dependency install and the repo's
tooling does not already cover the GitHub API.
